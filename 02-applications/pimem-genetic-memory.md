## 第一章　三种三元组的本质区分与第一性原理

### 1.1　PEF 本体三元组：单次推演的准入约束

【原构想】公式：P + ΔV → J。P 是主体快照，带 Source_Ref（传感器 ID、时间戳、校准状态）；ΔV 是带 SI 量纲的变量操作；J ∈ {PASS / FAIL / MISMATCH} 是二三值裁决结果。其作用域是单次推演提案的准入本体约束：控制每一次进入系统的数据是否合法。主体标识依靠 Source_Ref，解决数据来自哪里的问题。

【原构想】其结构性短板在于：多次迭代推演之后，运行时主体 P 的内部定义可以被潜移默化改写；Source_Ref 只管来源，不管推演过程中主体本身有没有被偷偷改掉含义。这是原始构想稿明确指出的缺口，也是 PIMEM 立项的直接动因。

### 1.2　传统知识图谱三元组：素材检索库

【原构想】格式：(实体 E, 关系 R, 实体 E')，存储事物之间的关联关系。主体标识依靠实体文本或字符串 ID；运行逻辑是大模型抽取关系存入图库，查询时做图遍历，召回关联实体与关系片段，喂回 LLM 做推理。本质是素材检索库，目标是找回历史相关文本片段。

【原构想】其三个致命缺陷：其一，实体 ID 绑定文本描述，文本改写、别名漂移，实体身份随之漂移；其二，图谱只记录有什么关系，不区分什么是不变基线、什么是演化变量，没有强制的基线快照；其三，推理靠 LLM 理解关系，数据库只做检索，无法原生校验原始主体有没有被篡改。

### 1.3　PIMEM π-基因链三元组：主体生命周期演化谱系

形式：(Πanchor, Pbase, Chain(ΔVi → Ji))。

【原构想】Π_anchor 是 π 锚基因编号，取自 π 数位序列（可替换 UUID / 雪花 ID，优选 π 但不强绑定），主体实例初始化时一次性分配，全生命周期永久固定、不可修改，与主体的文本描述、变量演化、输出结果完全解耦。P_base 是原始主体基线快照，写入注册表后只读锁定，是基因的原始模板。Chain(ΔV_i → J_i) 是演化基因链，有序链表记录每一轮迭代的变量输入与裁决结果；变量与结果允许不断变化，但全部演化链条挂载在同一个不变的 Π_anchor 之下。

第一性原理：身份基因（Πanchor) 不变；外部状态、变量、推演结果允许演化；任何时刻通过基因锚反向查表取回原始基线 Pbase，与当前运行中的主体做结构比对，即可检测主体漂移。　　(1.1)

【原构想】关键对比一句话：图谱三元组存事物之间的关系，做素材检索；PEF 本体三元组约束单次推演的数据准入合法性；PIMEM 三元组记录同一个主体的完整演化谱系，做身份锁定、基线溯源与漂移检测。

## 第二章　PIMEM π-基因链记忆仓库：形式化定义与运行流程

### 2.1　注册表与只读基线

【AI补全】注册表是锚到基线的永久映射：Πanchor ↦ Pbase。原始构想稿要求其永久只读；本文档补全其工程实现：注册表条目写入时同时登记基线内容摘要 Dbase = SHA-256(canon(Pbase))，任何读取都伴随摘要复验，任何改写在复验时被拒绝。这就是注册表哈希锁：只读性不依赖实现者的自觉，而依赖密码学校验。

【AI补全】基线快照的字段分类是漂移检测可Operational化的前提。原始构想稿未定义哪些字段属于关键定义，本文档补全为两类：

· 定义类字段（DEF_FIELDS）：主体身份与规格承诺，如名称、目标区间（含量纲与单位）、执行器类型、单位制。此类字段参与漂移比对，任何运行期变更都是漂移。

· 状态类字段（STATE_FIELDS）：允许演化的运行时状态，如当前模式、当前温度。此类字段的变化是演化而非漂移，记入演化链但不告警。

【AI补全】这一分类直接承接 V2.5 的 A1 公理（真值参照：spec-as-region）：定义类字段就是规格区间 R_spec 在记忆层的投影，状态类字段就是归一化状态向量 S_norm 的记忆层投影。漂移检测因此与 ρ 的本体定义同源，而不是发明第二套真值。

### 2.2　运行流程四阶段

#### 阶段一：基因初始化（主体第一次实例化）

· 生成唯一 Π_anchor（优选 π 序列数位，如取 π 前 8 位 31415926；可替换其它 ID 方案）。

· 捕获此时主体完整快照作为只读基线 P_base 写入注册表，同时登记基线摘要锁。

· 创世上链（本文档新增，见第四章 4.5 节）：向审计链写入 GENESIS 记录，内容含锚编号与基线摘要，使注册表本身可审计。

· 初始化空演化链 Chain = [ ]。

【原构想】注意：本阶段属于记忆模块，不改动 PEF 内部的 P；PEF 内部照常使用带 Source_Ref 的 P 做每一轮推演校验。

#### 阶段二：正常推演循环（复用 PEF 整套 P/E/F/M 五域）

PEF 运行：Pcurrent + ΔVi 经 P/E/F 域产出 ρi 与裁决 Ji，J = FAIL 当且仅当 ρ ≥ λ，其中 λ 由 MOD3 三态审问给出（MOD3=0→λ=1.0 稳定推进；MOD3=1→λ=0.8 临界复核；MOD3=2→λ=0.5 毁灭性证伪）。PIMEM 把本轮 (ΔVi, Ji) 追加挂载到该 Πanchor 的演化基因链上。Πanchor 全程不变；Pcurrent 是运行时主体，可被变量影响发生形态变化。

#### 阶段三：漂移校验触发（定时 / 关键节点触发）

【原构想】拿当前运行时主体 P_current，用 Π_anchor 查表取出原始 P_base，对定义类字段做结构比对：一致则正常；关键定义发生偏移则判定主体漂移，抛出告警。重点：漂移校验不是靠向量相似度，不是靠图遍历，而是锚索引拿到原始只读基线，直接做结构比对。传统图谱与向量库只能靠语义猜是不是同一个东西；PIMEM 的锚是独立指针，直接拿到创世版本做比对。

#### 阶段四：继续推演或漂移处理

【AI补全】无漂移：继续运行。检测漂移：可选择回退基线 P_base、阻断推演、告警三种处置，由上层策略决定。本文档建议的默认处置次序为：先阻断（防止漂移状态继续写入记忆），再告警（人工介入），最后才考虑回退（回退是重操作，涉及事实空间一致性，见第七章 R8 并发条款）。

### 2.3　与 PEF 主架构的边界

· 【原构想】PEF 本体（V2.5A）负责：每一轮提案的本体过滤、P/E/F 权力分立、ρ-λ 裁决、哈希审计链、MOD3 审问。π 在这里做调度种子与哈希盐值，支持替换为 step mod k。

· 【原构想】PIMEM 负责：长期记忆、主体身份基因、演化谱系、主体漂移检测。π 在这里只是可选 ID 发生器；整个模块可以关闭、可以替换别的 ID 生成器，不破坏 PEF 的 A4 公理（搜索种子排他律：种子必须来自预存确定性序列或确定性函数，禁止反馈构造）之种子可替换性质。

· 【原构想】PIMEM 不修改 PEF 的三元组本体公理，是应用层外挂记忆仓库。第四项是可选扩展，不是架构成立的必要条件。

### 2.4　π 的四项用途汇总

· 用途一：MOD3 调度种子，生成三态审问阈值 λ（基础设施）。

· 用途二：哈希链盐值，抵抗重放攻击（基础设施）。

· 用途三：算子库确定性映射 π-Tool Mapping Matrix（工程检索）。

· 用途四（本文档主体）：PIMEM 记忆仓库——π 数位作为主体基因锚 Π_anchor，构建主体-变量-结果演化基因链，长期记忆、基线溯源、对抗主体漂移（外置记忆扩展）。

## 第三章　PIMEM-Tree：Π-Anchor + MOD 度量的树状分叉记忆

### 3.1　从线性链到树：核心构想

【原构想】在 PIMEM 基础上，不再只有单一线性 Chain，引入 MOD 状态作为演化分支度量单位：当主体推演过程中偏差率 ρ 越过阈值 λ，或状态质变刻度到达时，主体发生状态跃迁，记忆节点产生分叉，生长出树状记忆谱系。每一条分支节点保留：π 基因锚、原始基线引用、触发分叉的 MOD 度量、当时的变量 ΔV、裁决 J、子分支引用。目标：即便经过海量长文本迭代、主体发生质变转向其他状态，依然完整保留每一条演化路径，完整回溯每一条逻辑链的来龙去脉。

【原构想】固有约束保持不变：根节点的 Π_anchor（基因锚）永久不变；哪怕主体已经演化、分叉、转变成完全不同的状态，根锚永远指向最开始的 P_base 创世基线。MOD 在这里充当分支切换的度量标尺，不是用来生成锚 ID，与 PEF 本体的 MOD3 审问是两套独立 mod 语义。

### 3.2　树节点结构（形式化定义）

【原构想】单个记忆树节点 Node 的字段定义如下（字段名为工程命名，与原始构想稿的数学记号一一对应）：

· anchor：根基因锚 Π_anchor（全局不变，自根节点继承）

· node_id：本分支节点局部编号

· kind：节点类别：ROOT 根（创世基线）/ FACT 事实 / BRANCH_FAIL 失败分叉封存 / BRANCH_QUANTUM 质变分叉 / REHEARSAL 预演隔离。【AI补全】原始构想稿未给节点分类，该分类是预演-事实切割在数据结构上的落点

· mod_metric：MOD 度量：分支跃迁的离散量化标尺（语义见 3.4 节）

· P_snap：本节点当下主体快照（非原始基线，可演化；根节点 P_snap = P_base 且只读）

· dV_trigger：触发本节点生成的变量 ΔV

· J：裁决结果 ∈ {PASS, FAIL, MISMATCH}（预演隔离节点为 QUARANTINED 标记）

· rho, lam：分叉时刻偏差率与阈值（记录裁决语境，供复盘）

· parent：父节点指针

· children：子分支列表（分叉出口）

· audit_n：审计链序号引用：本节点被 M 层锁定时的判定轴事件编号；预演节点为空。【AI新设计】双向索引的前向指针，见第四章

· self_digest：节点自证摘要 = SHA-256(anchor ‖ node_id ‖ parent ‖ P_snap ‖ ΔV ‖ J ‖ ρ ‖ λ ‖ mod_metric ‖ audit_n)。【AI新设计】使每个节点可独立验篡改，不依赖全链重算

· state_digest：本节点状态摘要 = SHA-256(P_snap)。【AI新设计】用于与审计链记录中的 S_t 摘要比对（一致性不变量）

【原构想】根节点 Root：Π_anchor 固定，P_snap = P_base（只读原始基线），parent = null。所有分叉出来的全部子节点，无论多少代，全部继承同一个根 Π_anchor；哪怕主体已经跃迁、形态彻底改变，通过这个根锚总能跳回最初创世基线。

### 3.3　两种分叉场景（沿用原始构想稿定义）

· 【原构想】FAIL 分叉：F 域裁决 FAIL，主体原有路径不可继续，开辟新分支尝试另一组变量集合；旧节点原地封存，历史不丢失。

· 【原构想】状态质变分叉：ρ 虽然 PASS，但 mod_metric 到达设定刻度，主体发生性质转变，主动开启新分支，代表主体演化成另一种形态。

【原构想】通俗实例（原始构想稿原例，第九章 E1 给出完整推演与 demo 输出）：原始主体 P 为温控系统 A（Π_anchor = X）。分支 0：正常升温，ρ 持续合格，线性向下延伸；在节点 N 处 ρ ≥ λ 触发 FAIL，温控进入保护状态，产生子分支 1：主体快照变为「温控 A-保护模式」；继续推演，保护模式下进一步演化，又产生分支 2：「温控 A-停机模式」。所有分支根锚永远是 X，随时可以回到最初的温控系统 A 原始基线。

### 3.4　MOD 度量：从构想参数到确定性规则

【原构想】原始构想稿对 mod_metric 的定义是离散跃迁标尺：当推演中满足 ρ ≥ λ 或到达设定刻度时主体发生状态跃迁，不直接覆盖旧节点，而是生成子节点作为分叉分支，旧节点完整保留。构想的计数规则是每分叉一次 mod_metric += 1，但何时复位、以什么事件为计数基准未定义——这会使其退化为手工维护的参数，评审无法复算。

【AI补全】本文档将 mod_metric 确定性化为：【AI补全】mod_metric(node) = 该节点所在分支自上一次质变分叉（或根）以来累计的已锚定事件数，其中每一次 M 层锁定事实事件计 1，分叉事件使新分支从 0 重新计数。质变触发条件：当前分支连续锁定事实数达到预设刻度 K_quantum。该规则的全部输入都是审计链事件计数 n（判定轴驱动、单调递增、不可回退，与 A0 因果顺序公理同源），因此任何第三方都可以从审计链复算整棵树的 mod_metric 值——度量标尺本身不可被悄悄拨动。demo 采用 K_quantum = 2 演示质变分叉。

### 3.5　完整运行流程（结合 PEF 五域）

· 【原构想】步骤一，初始化根节点：主体第一次实例化，分配根 Π_anchor，写入只读 P_base，生成树 Root 节点，mod_metric = 0，children 为空（严格档下同时创世上链）。

· 【原构想】步骤二，PEF 正常推演循环 P→E→F→M：得到当前 ρ、λ、J，运行主体快照 P_current，本轮变量 ΔV_i。

· 【原构想】步骤三，分支判定（记忆树层，PIMEM 模块）：情形①，ρ < λ 且 mod_metric 未达跃迁刻度——在当前节点下追加线性子节点，延续当前路径；情形②，触发分叉——诱因 A：F 域裁决 J = FAIL；诱因 B：J = PASS 但 mod_metric 抵达预设跃迁刻度。

· 【原构想】步骤四，触发分叉：当前状态完整封存为旧节点，不做任何覆盖；创建新的子分叉 Node，继承根 Π_anchor；填入触发分叉的 ΔV_i、J、ρ、λ、新的主体快照 P_snap；mod_metric 复位；挂载到父节点 children 列表；后续推演在新分叉节点继续运行。

· 【原构想】步骤五，回溯与遍历：任意子分支节点顺着 parent 向上回溯，一路回到 Root 根节点；拿到根节点的 Π_anchor，读取 P_base 原始基线，做漂移校验。优势：哪怕某一条分支里主体已经完全演变成另一个事物，整条演化链条全部完整保存在树上，没有被覆盖、没有被丢失；长上下文再长、迭代再多，所有分支线路可遍历、可重放。

### 3.6　与知识图谱、线性 PIMEM 的三方差异

【原构想】传统知识图谱：演化表达靠新增关系，图呈网状；身份锚是实体字符串 ID，依附文本；发生状态跃迁时新增实体或新增关系，没有原生分叉版本管理；查询需要图遍历，容易混淆不同演化版本的同一个实体。它擅长不同实体之间的关联。

【原构想】早期 PIMEM（线性链）：单条链表顺序追加；根锚不变；状态跃迁直接追加到链尾部，无法表达并行分支；只有一条时间线，不能记录多套并行推演假设。

【原构想】本方案（树状记忆）：多分支演化树，父子节点全部继承同一个根锚；触发阈值或 mod 刻度时生成全新子分叉节点、旧节点完整封存不覆盖；节点向上回溯得到完整演化路径，根锚直达创世基线，支持同时保存多条并行推演分支。它擅长同一个同源主体内部、随推演产生的多版本多分支演化谱系。

【原构想】重点区分（原始构想稿原文存档）：知识图谱擅长不同实体之间的关联；这套树记忆擅长同一个根主体内部随推演产生的多版本、多分支演化谱系。图谱很难区分「是全新实体」还是「同一个实体演化出来的分支版本」；而这套树结构靠根 Π_anchor 天然区分：只要根锚相同，就是同源主体的不同演化分支。

## 第四章　审计链-记忆树双向索引（核心增量设计）

【AI新设计】本章回应设计问题：树记忆和 PEF 哈希审计链如何联动——每个记忆节点带上审计链 n 编号，实现审计链-记忆树双向索引。

### 4.1　动机：两条时间线的正交性

【AI新设计】V2.5 的哈希审计链是 M 层维护的全局事实时间线：每条记录 (n, D_n, content, H_n)，其中 n 由判定轴事件驱动（每锁定一次 ΔV_t 则 n ← n+1，单调递增不可回退，对齐 A0 因果顺序公理），D_n 是调度轴 π 尾数盐值，content = (S_t, ΔV_t, J_t)，H_n = SHA-256(H_{n-1} ‖ n ‖ D_n ‖ S_t ‖ ΔV_t ‖ J_t)，H_0 = SHA-256(genesis)。它回答「全局发生了什么、有没有被篡改」，但不知道「这条事实属于哪个主体的哪条演化分支」。

【AI新设计】PIMEM 记忆树是主体局部的谱系结构：回答「这个主体怎么一步步演化的、走了哪些分支」，但节点自身若无密码学自证，树可以被静默改写而不影响审计链。两条时间线天然正交：审计链有全局完整性、无主体语义；记忆树有主体语义、无跨模块完整性证明。双向索引就是让两者互为证明：树给链提供主体归属，链给树提供不可篡改性背书。

### 4.2　索引结构与双写协议

· 【AI新设计】前向索引（树 → 链）：每个已锚定节点（kind ≠ REHEARSAL）携带字段 audit_n = 该节点被 M 层锁定时的审计链序号。根节点 audit_n = 1（创世上链）。预演节点 audit_n = 空，这是预演/事实切割在索引层面的形式化表达。

· 【AI新设计】反向索引（链 → 树）：PIMEM 维护映射 n → (Π_anchor, node_id)。审计链记录本身不改格式、不增字段（严格档），映射表由 PIMEM 在锁定事件发生时同步登记。

· 【AI新设计】双写协议：M 层每次锁定（n 递增）必须与 PIMEM 的三个动作在同一事务语义内完成——创建树节点（含 self_digest 与 state_digest）、登记反向索引、节点写入 audit_n。双写不完整则该事件两侧都不可见（要么都不存在，要么都存在），避免「链有树无」的幽灵事实或「树有链无」的孤儿节点。

### 4.3　三条一致性不变量与篡改检测矩阵

INV-1 存在性（前向）：对每个已锚定节点，链上存在记录 n = audit_n，且从 H_0 到该记录的哈希链重算完整。 Coverage：树节点不能凭空指向不存在的事实。

INV-2 一致性（前向内容绑定）：节点 J 与链记录 J_t 相等；节点 state_digest 与链记录 S_t 的规范序列化摘要相等；D_n 可由调度轴指针位置复算。Coverage：节点内容与链上内容逐字段对得上，且盐值可复算（抗重放）。

INV-3 完备性（反向）：扫描审计链中属于该主体的全部事件（经反向索引或 S_t 内嵌锚标签），每一条都存在对应树节点。Coverage：链上有、树上无的「幽灵事实」被查出——有人绕过记忆树直接写链也会现形。

INV-4 注册表自证（创世）：注册表基线摘要与创世记录中 P_base_digest 一致，且创世记录本身在哈希链保护之内。Coverage：记忆仓库的根（锚注册表）纳入审计范围，TOFU 缺口闭环。

【AI新设计】篡改检测矩阵：篡改树节点快照 → self_digest 失配（V5 检出）；篡改链记录内容 → 哈希链断裂（V2 检出）；篡改 audit_n 指针 → INV-1/INV-2 失配；删除或绕过树节点写链 → INV-3 完备性扫描失败；篡改注册表基线 → INV-4 与基线摘要锁双重拒绝（V1 检出）。

### 4.4　与 V2.5 审计协议的兼容性：两档实现

【AI新设计】严格档（demo 采用，默认档）：审计链格式 (n, D_n, content, H_n) 与 H_n 公式一字不改；content 保持 (S_t, ΔV_t, J_t)；双向映射完全外置于 PIMEM。代价：INV-3 的完备性扫描依赖 PIMEM 侧映射表，映射表自身的增删需要由 INV-1/INV-2 交叉验证兜底（映射指向的 n 必须真实存在且内容一致，链上事件若无映射则视为未挂载主体事件，由定期对账任务补扫）。

【AI新设计】增强档（可选升级，需 V2.6 预留）：利用 S_t 是自由结构状态向量这一点，在 S_t 内增补可选字段 subject_tag = (Π_anchor, node_id)。H_n 公式不变（S_t 整体进哈希），链记录因此天然携带主体标签，INV-3 扫描无需外置映射表即可全局执行。该字段为可选增补，不改变公式与既有记录语义。

【AI新设计】创世上链的两档说明：严格档下 GENESIS 记录的 content 采用扩展事件结构（字段为 event=GENESIS、anchor=锚编号、P_base_digest=基线摘要，demo 即如此），这与 V2.5 定义的 content = (S_t, ΔV_t, J_t) 模式不同，属于 PIMEM 侧驱动的扩展事件类型；严格集成方案是 M 层预留锚定与修订等记忆治理事件类型，由 V2.6 版本决策。本文档诚实声明：demo 中 M 层锁定由 PIMEM 模拟驱动。

### 4.5　验证成本与检查点优化

【AI新设计】全链重算成本 O(n)：链越长验证越慢。补全设计：【AI补全】每 C 条记录（如 C = 64）将当前链头 H 发布为检查点（checkpoint），日常验证只从最近检查点重算至链尾，成本降为 O(C)；检查点哈希可进一步组织为 Merkle 树，支持单条记录的存在性证明 O(log n)。检查点本身写入受保护存储或外部公告（如日志服务），防止单点改写。该优化不改变链公式，是纯应用层工程。

## 第五章　作为 LLM 外置记忆体：长文本记忆应用设计

### 5.1　LLM 长文本记忆的真实痛点

· 上下文窗口有限：超长会话必然发生早期信息出窗，模型对「最初的需求定义」只剩模糊印象。

· 注意力稀释与中间丢失：即使信息在窗内，长上下文中部内容的召回率显著下降（lost in the middle 效应），关键约束被淹没。

· 主体漂移：几十轮迭代后，AI 对「我们到底在做什么」的内部表征悄悄变形——术语含义漂移、需求口径漂移、人格语气漂移；语义检索召回的是相似文本，不是同一主体的事实基线。

· 假想污染：预演、试探、被否决的方案与已确认事实混在同一个上下文里，模型分不清哪段是定案、哪段是废稿。

### 5.2　总体架构：推理核 + 双通道检索网关 + PIMEM

【AI新设计】架构分四层：【AI新设计】第一层 LLM 推理核（不承担记忆职责，只对当前窗口负责）；第二层检索网关（关键组件，下述）；第三层 PIMEM 记忆仓库（事实空间记忆树 + 预演空间暂存 + 注册表）；第四层 PEF 本体（提供每轮推演的 ρ-λ 裁决与 M 层锁定事件流，PIMEM 只读消费）。检索网关提供两个寻址通道：

· 锚寻址（确定性通道）：由 Π_anchor 直接取回 P_base、指定路径、指定节点。O(1) 查表，零语义歧义，用于身份校验、基线对账、谱系回放。

· 语义寻址（概率通道）：向量检索按相关度召回候选节点，但每个候选必须携带 node_id + self_digest，由网关向 PIMEM 验证真伪后才允许回注（防幻觉记忆：模型可能记错内容，PIMEM 不允许）。

【AI新设计】两通道关系一句话：语义通道负责找得准，锚通道负责验得真；先语义后锚定，是本设计的核心纪律。

### 5.3　写入路径：什么可以进记忆

· 【原构想】事实节点：仅 F 域裁决 PASS 且 M 层锁定的事件，双写进入事实记忆树并获 audit_n（对齐 V2.5 预演/事实切割）。

· 【AI补全】分叉记录节点：FAIL 裁决本身是不可逆事实（该提案被否决这件事发生了），FAIL 分叉封存节点上链并获得 audit_n；被拒提案的状态快照不入事实空间。

· 【AI补全】预演节点：预演空间的试探推演不写入 M 层事实记忆；短期留存供复盘，TTL 过期丢弃或归档冷存。回注默认排除预演节点，除非调用方显式声明进入预演模式。

· 【AI新设计】写入只走结构化 API：LLM 不得用自然语言复述直接改写记忆（防回注漂移，见 5.5）。

### 5.4　读取路径与回注契约

【AI新设计】回注是本设计的工程核心：把记忆注入 LLM 上下文的方式决定了记忆是否真的生效。回注包分四级预算：【AI新设计】

· L1 基线卡（常驻）：P_base 全文（小对象时）或摘要 + Π_anchor + 基线摘要锁 + 定义类字段清单。每轮都在上下文中的「身份锚」，规模控制在数百 token。

· L2 路径骨架（常驻）：当前分支从根到叶的节点 ID 序列 + 每节点一行摘要（ΔV、J、mod_metric），不含节点原文。给模型「我们从哪来」的骨架感。

· L3 节点原文（按需）：被锚寻址或语义寻址选中的节点完整快照，以原文块呈现。

· L4 审计视图（仅审计任务）：哈希链检查点、INV 扫描结果，仅供审计类请求。

【AI新设计】原文块契约：所有 L3 原文以固定包装呈现——BEGIN-VERBATIM digest=… … END-VERBATIM，并附该节点 self_digest。模型被提示：原文块内容按只读事实对待，引用时不得改写；若模型需要在回答中转述，转述与原文的差异由调用方负责比对。这把「AI 复述走样」从隐性风险变成可校验差异。

### 5.5　反回注漂移的三条纪律

· 【AI新设计】纪律一：读走语义、写走结构。LLM 对记忆的任何写入请求必须表达为结构化操作（ propose_node / propose_branch ），经 PEF 本体校验与 M 层裁决后才发生；自然语言中的「我认为之前的结论是……」不产生任何写入。

· 【AI新设计】纪律二：回注必附摘要。每个回注元素携带 digest，长会话结束后的 shrunk 上下文重建时，重建结果与 PIMEM 逐节点比对摘要，失配即告警（上下文重建本身也被审计）。

· 【AI新设计】纪律三：预演显式标记。回注的预演节点必须携带 REHEARSAL 标签与来源分支，禁止与事实节点混排；模型提示词中要求对预演内容使用「假设/试算」限定词表述。

### 5.6　跨会话生命周期：冷启动-热态-归档-恢复

【AI新设计】冷启动：新会话以 Π_anchor 开场，网关取回 L1+L2 注入，模型在数百 token 内重建「我是谁、做过什么、走到哪个分支」。热态：每轮推演经 PEF 裁决持续双写；漂移校验按关键节点触发（每 N 轮或每分支切换）。归档：会话结束生成 handoff 节点（当前快照 + 开放变量清单 + 未决问题），树封版归档，分支按老化策略落盘。恢复：跨会话恢复即以锚取回 handoff 节点与路径骨架，主体连续性由 audit_n 链保证——新会话不是「看摘要猜状态」，而是「沿审计链回到上次事实」。

### 5.7　与向量库 / RAG 的关系：互补而非替代

【AI新设计】向量库回答「和什么相似」，PIMEM 回答「是谁、从哪来、变过没有、可不可信」。RAG 的召回精度问题（别名漂移导致漏召回、相似文本导致误召回）在混合架构中获得双重保障：向量漏召回时锚寻址兜底身份事实；向量误召回时锚验证拒绝未锚定内容。知识图谱侧重实体间关系的广度检索，PIMEM-Tree 侧重单主体演化谱系的深度保真，三者构成完整的 Agent 记忆栈。

## 第六章　能力边界：PIMEM 能在什么意义上提高 LLM 长文本记忆

### 6.1　有效的五类场景（能提高）

· 【AI新设计】身份一致性：超长会话与跨会话中「_same 主体」不串味。锚寻址让每次回答前的身份基线是查表取得的，不依赖模型对几十轮前内容的模糊记忆。

· 【AI新设计】长程事实可溯源：任何当前结论都能沿 audit_n 反向回放出一串可验证的证据链；当用户质疑「你为什么这么说」时，答案不是模型复述，而是节点原文 + 哈希证明。

· 【AI新设计】漂移拦截：LLM 在第 40 轮偷偷改变了需求口径，结构比对立即告警——这是纯语义记忆做不到的，因为语义漂移在向量空间里往往平滑得不可见。

· 【AI新设计】并行假设管理：多条推演分支（预演/备选/被否决）不互相覆盖、不污染事实，长文本中的「如果当初走另一条路」成为可回放对象。

· 【AI新设计】审计可信：对外发布或合规场景，记忆内容可用哈希链自证未篡改；这在纯向量或图谱记忆里是缺失能力。

### 6.2　无效的五类场景（不能提高，需要其它组件补位）

· 【AI新设计】语义相关性判断：锚寻址不会告诉你「哪段记忆与当前问题相关」。相关性仍需语义通道（向量检索或 LLM 自身判断）。PIMEM 提高记忆的正确性，不直接提高记忆的恰当性。

· 【AI新设计】文本压缩与摘要生成：PIMEM 不做内容压缩；把 1000 轮历史塞进 2000 token 预算的摘要工作仍需 LLM 或抽取规则完成。

· 【AI新设计】单轮内的注意力问题：lost in the middle 是 Transformer 架构现象，PIMEM 无法修复；它只能通过减少必须常驻的内容（L1/L2 骨架化）间接缓解。

· 【AI新设计】隐式常识与语用推理：模型自身的世界知识与语用能力不在记忆仓库职责内。

· 【AI新设计】生成质量本身：记忆只保证「依据正确」，不保证「写得更好」；质量仍取决于模型与提示工程。

### 6.3　定量边界（设计主张，待实测校准）

· 【AI新设计】回注预算：L1+L2 常驻控制在 1k-2k token；超过预算时优先裁剪 L3，禁止裁剪 L1（基线卡缺席即身份缺席）。

· 【AI新设计】完备性扫描成本：INV-3 全量扫描 O(链长)，只应在关键节点触发；日常用增量对账。

· 【AI新设计】树遍历成本：回溯 O(深度)；并行分支全遍历 O(节点数)，受第七章 R1 分支上限约束。

· 【AI新设计】可重放性的诚实边界：物理主体的重放是确定性的；LLM 主体的「路径重放」是语义近似的（同一 ΔV 不同采样可能得到不同表述），重放保证的是「事实顺序与裁决结果一致」，不保证「文本逐字一致」。这一区别必须在产品语义中明示。

【AI新设计】一句话结论：PIMEM 把 LLM 记忆的「正确性」从概率语义匹配升级为确定性结构校验，并把「恰当性」留给语义通道——正确性可验证，恰当性不可验证，两通道纪律性组合才是完整答案。

## 第七章　风险清单与缓解设计

【AI新设计】原始构想稿已识别三项风险（R1 分支爆炸、R2 两套 MOD 概念混淆、R3 预演污染），本章保留并补全九项。每项按「风险 → 后果 → 缓解」陈述。

### R1 分支爆炸（原构想已识别）

【AI补全】风险：每次 FAIL 都生成子节点，复杂场景树节点指数增长。缓解：配置分叉上限与分支老化归档（低频分支落盘不驻内存）；补全：等价子树合并——内容摘要相同的兄弟子树合并为一个节点，多父引用计入共享引用表，谱系完整性由引用表保证。

### R2 两套 MOD 概念混淆（原构想已识别）

【原构想】风险：MOD3（PEF 本体，切换审问阈值 λ）与 mod_metric（PIMEM 记忆树，分支跃迁计数）命名相近，评审极易混淆。缓解：文档严格区分命名（本文档全文遵守）；代码层进一步隔离——MOD3 属于 PEF 调度域，mod_metric 属于记忆模块，两者仅通过「都已锚定到审计链事件计数」间接相关。

### R3 预演污染（原构想已识别）

【AI补全】风险：预演空间产生的分叉树若写入 M 层事实记忆，大量假想推演污染记忆仓库。缓解：只有 M 层锁定 PASS 的状态才生成正式持久记忆树节点（原始构想稿规则）；补全：节点三级分类（3.2 节 kind 字段）+ 回注显式标记（5.5 纪律三）+ 预演 TTL 灰度留存。

### R4 TOFU 创世信任缺口（新识别）

【AI新设计】风险：整套体系的信任锚点是创世基线 P_base；若基线捕获时刻就错了（错误快照、错误单位、恶意注入），系统将「正确地错下去」——哈希链只能证明基线未被改，不能证明基线本来对。缓解：创世宽限期——注册后 T 个周期内允许双人复核并作废重建（作废记录上链，锚编号作废不复用）；宽限期后锁死。同时 P_base 必须携带 Source_Ref 与量纲指纹（对齐 A3），基线来源可追溯。

### R5 基线纠错悖论（新识别）

【AI新设计】风险：P_base 只读，但真实世界存在「基线本身需要修订」的合法场景（规格变更、评审纠正），只读性与可纠正性表面冲突。缓解：补丁层设计——P_base 永不改写；建立 SUPERSEDE 修订链节点（旧基线 + 修订原因 + 新生效基线版本），漂移比对使用「生效基线 = P_base + 已授权补丁序列」，修订链同样上链审计。历史漂移轨迹不因修订而消失。

### R6 合规冲突：不可篡改 vs 被遗忘权（新识别）

【AI新设计】风险：GDPR 等法规赋予数据主体删除权，而 PIMEM 的设计目标是不可篡改与永久留存，两者直接冲突。缓解：加密撕裂（crypto-shredding）——P_snap 敏感字段加密存储，密钥单独保管；合规删除 = 销毁对应密钥，密文留存但永久不可读，链上摘要保留（证明该记录曾存在且被合规销毁）。审计能力与删除权并存。

### R7 验证成本 O(n)（新识别）

【AI新设计】风险：全链重算随链长线性增长，长生命周期主体验证变慢。缓解：见 4.5 检查点与 Merkle 化。

### R8 并发与单写瓶颈（新识别）

【AI新设计】风险：审计链 n 全局单调、M 层单写者，多 Agent / 多会话并发锁定会竞争写入口。缓解：短周期内预演不受影响（预演不上链）；事实锁定经 M 层串行化队列；多机部署需共识机制，超出 V2.5 单机范围，声明为部署约束。漂移处置次序（先阻断后回退）在并发下尤其重要：回退必须先确认无其他分支依赖被回退状态。

### R9 语义漂移盲区（新识别）

【AI新设计】风险：结构比对抓不住「字段没变、含义变了」的漂移——target_range 数值不变但单位从摄氏改为华氏、字段语义被重新解释。缓解：定义类字段绑定量纲指纹（字段名 + 单位 + 区间 + 类型），单位变更即指纹变更即漂移告警（demo 场景中的 unit 字段即此设计）；定期基线重述对账：让 LLM 用自然语言重述基线，人工比对重述与原始定义的语义一致性——这是唯一需要人工语义判断的环节，也是结构性盲区的兜底。

### R10 回注改写（新识别）

【AI新设计】风险：记忆回注到 LLM 后，模型对原文的隐性改写会在后续对话中扩散。缓解：5.4 原文块契约 + 5.5 三纪律。

### R11 锚可预测性（新识别）

【AI新设计】风险：π 数位是公开常数，顺序分配的锚可被第三方预测（预占、撞库、枚举探测）。缓解与 V2.5 对 A4 的处理同构：承认确定性 ⟹ 可预测，安全不来自不可预测，而来自注册表访问控制 + 创世上链（第三方可验证锚的真实分配时刻）+ 可选的秘密盐化（锚 = π 数位段 ⊕ 注册表秘密盐的哈希，牺牲纯公开可复算性换取不可枚举，属部署选项）。

### R12 时间源信任（新识别）

【AI新设计】风险：n 单调性依赖判定轴时钟与单写者诚实性；系统时钟回拨或 M 层被绕过将破坏因果链。缓解：n 由逻辑事件计数驱动（非墙上时钟，对齐 A0），物理时钟仅做辅助标注；M 层写入口权限收敛 + 哈希链完整性与 INV-3 完备性双重监测，绕行即现形。

## 第九章　实事例推演

### 9.1　E1：温控系统 A（原始构想稿实例的完整化）

【原构想】原始构想稿给出温控系统 A 的通俗例子：正常升温路径、ρ ≥ λ 触发 FAIL 进入保护模式、再演化出停机模式，所有分支根锚不变。本文档将其完整化为可执行场景并接入 V2.5 裁决与审计链（demo 全量输出见第十章）：

· 【AI补全】创世：Π_anchor = 31415926（π 前 8 位，真实计算），P_base = {name: 温控系统A, target_range: [83.0, 87.0] degC, actuator: PID加热器, unit: degC}，创世上链 n=1。

### 9.2　E2：AI 长会话需求主体漂移（AI 补全实例）

【AI新设计】场景：某 Agent 承接「结算引擎」需求，创世基线 P_base 含定义类字段 settlement_mode = T+1（T+1 日批量对账）。40 轮迭代中，对话自然演进：性能优化讨论引入「实时对账」概念作为对比项；第 41 轮用户问「那我们现在的对账延迟是多少」，模型回答基于「实时对账」展开方案——此时语义检索完全失灵：T+1 与实时的文本向量距离并不遥远（都在谈对账），向量库会照常召回相似段落，模型毫无异常感。

【AI新设计】PIMEM 视角：第 41 轮的运行时主体 proposal 中 settlement_mode = T+0（实时），锚索引取回 P_base，定义类字段结构比对失配 → 漂移告警 → 阻断该提案进入记忆，提示模型「当前主体基线承诺 T+1 批量对账，实时方案属于新提案，需要走 SUPERSEDE 修订链或新主体注册」。这就是「语义上都在谈对账、结构上主体已漂移」的典型场景：正确的记忆不取决于相似度，取决于身份。

### 9.3　E3：预演-事实双空间的迁移方案推演（AI 补全实例）

【AI新设计】场景：Agent 为存储系统做扩容决策，预演空间并行推进两个方案：预演分支 A（分库分表）推演 12 步后在第 13 步交叉表查询超规格（ρ=0.73 ≥ λ=0.5，毁灭性审问）FAIL——12 步预演全部封存为预演节点（audit_n=空），FAIL 事件本身上链（分叉记录），事实记忆不被 12 步假想状态污染；预演分支 B（读写分离 + 缓存）推演至 ρ=0.31 < λ=0.5 → PASS → M 层锁定 → 才产生第一个事实节点（audit_n=734）。

【AI新设计】事后复盘价值：分支 A 的 12 步预演节点短期留存（TTL 过期转冷归档），供「下次为什么不能再选分库分表」回放；事实树上只有 B 的通过记录。记忆仓库永远干净：事实树上没有那 12 步假想状态，但审计链上留有「分支 A 曾被认真推演并否决」的证据——决策历史完整，事实记忆无污染。

## 第十一章　结语

【原构想】PIMEM 把「主体的身份」与「主体的内容快照」彻底解耦，用不可变的数字锚与只读创世基线，为 AI 推演过程安装了一个可溯源、可审计、可分叉的记忆坐标系。它与知识图谱是互补的分工（关系广度 vs 谱系深度），与 PEF 本体是外挂的呼应（准入合法性 vs 谱系完整性），与向量检索是纪律性的协作（语义找得准 vs 锚定验得真）。

【AI新设计】本文档的三项增量设计——审计链-记忆树双向索引（让两条正交时间线互为证明）、LLM 回注契约（把记忆正确性从概率语义升级为确定性校验）、十二项盲区补全（把构想中隐含的工程风险显性化）——构成 PIMEM 作为一个可部署记忆组件的完整设计闭环。最小 demo 以真实 π 数位与真实哈希验证了四项核心声明；尚未实现的工程项与部署约束已在第五至八章诚实声明，构成 V1.1 迭代的自然路线图。

# P/E/F First Principle — 3-Minute Quickstart

> **这是什么**：PEF 架构的地基。不是审计工具，不是思考框架，是一套**可执行的拆解重构工作流**。

---

## 一句话

> **把任何有目的的行为拆到 P/E/F 就停，然后系统性地组合变量、试错、逼近真值。**

---

## 三个不可再分的原语

| 原语 | 全称 | 一句话 | 硬约束 |
|------|------|--------|--------|
| **P** | Primary Entity（主体） | 谁在做 | 必须有名字、边界、单位。不能是模糊的"系统" |
| **E** | Execution Variable（变量） | 用什么做 | 必须分流为 E_in（可控输入）和 E_out（不可控环境量）。混合变量 = 幻觉优化 |
| **F** | Final Result（结果） | 得到什么 | 必须可追溯至 (P, E, t)。F 不可先于原因 |

### 为什么不可再分？

- 拆"主体"→ 谁在拆？又是一个主体。**主体是执行拆解的起点，不可消除。**
- 拆"变量"→ 分类本身需要主体执行。**回到 P。**
- 拆"结果"→ "偏差"的判断需要主体定义。**回到 P。**

> P 不是形而上学真理，是**单主体、可追溯场景下的有用工程约定**。多主体/涌现/博弈场景下，P 可能是分布式的、涌现的、甚至不存在的。

---

## 五步工作流

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 1.拆解   │ →  │ 2.分流   │ →  │ 3.枚举   │ →  │ 4.试错   │ →  │ 5.逼近   │
│ Deconstruct│   │ Split    │    │ Enumerate│   │ Trial    │    │ Approximate│
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │               │
 任务→P/E/F      E→E_in/E_out    P固定+E分流    每组产生        因果追溯链
 三个原语         消除幻觉优化    组合空间可枚举   F=f(P,E,t)     比对哪组更接近真值
```

| 步骤 | 做什么 | 产出 |
|------|--------|------|
| **1. 拆解** | 任何任务 → P/E/F 三个不可再分单元 | P 声明、E 清单、F 定义 |
| **2. 分流** | 变量 → 可控 / 不可控 | E_in 清单、E_out 清单 |
| **3. 枚举** | P 固定、E 分流后，组合空间可枚举 | 有限的试错组合列表 |
| **4. 试错** | 逐组尝试，每组产生 F=f(P,E,t) | 可复现的结果序列 |
| **5. 逼近** | 因果追溯链比对，判断哪组更接近真值 | 方向收敛 + 下一轮细化 |

> **审计只是第 5 步的因果追溯链**——是手段，不是目的。能审计的方法很多，但能系统性指导"拆到哪、怎么分、怎么枚举、怎么逼近"的方法，不多。

## 和市面上"第一性原理"的区别

| 维度 | 市面上的"第一性原理" | P/E/F |
|------|---------------------|-------|
| **本质** | 思维方法（怎么想） | 拆解重构的执行标准（拆到哪、怎么组） |
| **拆解终点** | 主观的，每个人不一样 | 客观的，拆到 P/E/F 为止 |
| **变量组合** | 靠灵感和经验试错 | 系统性探索：P 固定 + E 分流后，组合空间可枚举 |
| **真值逼近** | 靠人判断"这次是不是更接近了" | 因果追溯链：每步 F=f(P,E,t)，可复现、可比对 |
| **可执行性** | 不可代码校验，靠人 | 可代码校验，每个字段有硬约束 |

> **市面上的第一性原理是指南针，P/E/F 是施工图。**
> 指南针告诉你方向，但不知道拆到哪算完、变量怎么分、组合空间怎么枚举、怎么验证这次试错是不是更接近真值。

## 一个具体例子

### 场景：AI 代码审计

| 步骤 | 传统做法 | PEF 做法 |
|------|---------|---------|
| **P** | 把代码喂给 LLM，LLM 说"这里有漏洞" | P 层显式声明：我是 GLM-4，边界是"静态代码分析"，单位是"漏洞/千行代码" |
| **E** | 代码内容 + 训练记忆，混在一起 | E 层分流：代码内容 = E_in（可控），系统时钟/文件系统 = E_out（不可控），严格隔离 |
| **F** | "这里有漏洞"——谁说的？用了什么？可复现吗？ | F 层追溯：每个结论带主体签名 + 变量哈希 + 时间戳，F=f(P,E_in,E_out,t) |
| **审计** | 人工复核 | π 锚坐标 + 哈希链，审计链可回放、可验证、防篡改 |

### 结果

- 你知道**谁**做的审计（P）
- 你知道**用了什么**变量（E_in/E_out 分流）
- 你知道结果**可追溯**到具体时刻和输入（F=f(P,E,t)）
- 你知道审计链**没有被篡改**（π 锚 + 哈希链）

## 诚实的边界

> 这不是万能框架。它有明确的边界，承认边界是为了在边界内做到极致。

1. **选择有三层，框架描述两层**：能描述选择的**约束条件**（E_out 定义什么不可能）和**后果**（F 预判每个选项的结果），但描述不了**选择的瞬间**本身——那是神谕，不可计算但可调用。且每步 1→N 都包含微小的 0→1，边界是渐变的，不是一刀切。

2. **声明范围内闭合，不是万能**：在单主体、可追溯、确定性工程系统内，一切可表达的东西都落在 P/E/F 里。但涌现行为、博弈互动、创造性生成——P/E/F 是不完备的。闭合 ≠ 完备。

3. **不保证找到真值**：保证的是"每步试错都可复现、可比对、可追溯"。真值在哪，要靠持续试错去逼近。

4. **可实证测试**：不是不可证伪的事后解释装置。接受和其他决策框架（成本收益分析、决策树、贝叶斯决策）的 A/B 对比。"系统性 P/E/F 拆解比纯直觉试错产生更好的变量组合探索"——这是一个可测试的假设，不是教条。

## 从理论到工具

第一性原理不是纸上谈兵——它已经落地为 6 个可运行的工程实例：

| 工具 | 第一性原理的体现 |
|------|----------------|
| **CLE 代码探针** | P 层主体声明 + E 层变量分流 + F 层结果追溯，用确定性探针验证审计器本身 |
| **CIC 幻觉检测仪** | 检测"空壳代码"——P/E/F 字段缺失或不一致的 AI 生成代码 |
| **PEF-π 防伪身份证** | π 锚坐标 + 哈希链，给代码发不可篡改的身份证 |
| **长文本审计** | 百万字级文本的 P/E/F 实体漂移检测 + 无锚论断识别 |
| **π 基因链记忆** | 用 π 锚为主体分配永久身份基因，解决 AI 长任务的主体漂移 |
| **多模型方言编译器** | 把任意大模型输出统一编译到 P/E/F 标准格式，消除方言偏差 |

> **三剑客不是三个独立工具，是同一套 P/E/F 第一性原理在三个正交维度上的部署**——先过滤幻觉（CIC）→ 再检测缺陷（CLE）→ 最后锚定信任（PEF-π）。

---

## 一句话总结

> **P/E/F 第一性原理 = 把"拆解重构"从模糊的思维方式，变成可执行的操作流程。**
>
> 它不保证你找到真值，但保证你每一步试错都可复现、可比对、可追溯。
>
> 它不是万能的，但在它的声明范围内，它是诚实的、可执行的、可验证的。

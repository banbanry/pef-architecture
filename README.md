# PEF Architecture

> **Anchored Determinism: a meta-architecture where the anchor produces the potential difference, and three primitives operate on it.**
> PEF is not a single system. It is a meta-architecture pattern: choose an unforgeable / unbreakable anchor, let the anchor produce the potential difference or coordinate, and then operate the P-E-F triad on top of it. Two systems are built on this pattern: one anchored by π (software), one anchored by thermodynamics (physics).

---

## What is PEF

PEF is an **anchored deterministic meta-architecture**.

The core pattern has two layers:

1. **The Anchor Layer** — an unforgeable or unbreakable foundation that produces the potential difference (or coordinate) on which the system operates. No anchor, no potential difference; no potential difference, no variable; no variable, no evolution.
2. **The Triad Layer** — three indivisible primitives **P (Primary Entity), E (Execution Variable), F (Final Result)** operating on the potential difference produced by the anchor.

**The triad definition is not universal — it is determined by the anchor.** Different anchors produce different kinds of potential difference, which require different definitions of P, E, and F. This is deliberate, not inconsistent.

---

## The Core Principle: Only the Anchor Produces Potential Difference

> *唯锚才有势差产生。*

A potential difference (or coordinate difference) is never self-generated by the triad. It must originate from the anchor.

- In the software system, the anchor is **π** — its digit sequence produces an unforgeable coordinate difference.
- In the physical system, the anchor is **thermodynamic law** — energy gradients, entropy, and conservation produce the potential difference that drives all state evolution.

If a variable or state transition cannot be traced back to a potential difference produced by the anchor, it is **illegitimate** — it is a hallucination, a forgery, or an ungrounded assumption. This is the first-principles foundation of PEF.

## Two Anchored Systems

PEF currently instantiates the meta-architecture in two domains. **The boundary between them is strict:** they share the meta-pattern (anchor → potential difference → triad), but their anchors, triad definitions, axioms, and mechanisms are different.

### System 1: Software PEF (π-Anchored)

**Domain:** AI-assisted programming, software verification, code audit
**Anchor:** The mathematical constant π (transcendental number, non-repeating, non-terminating digit sequence)

#### Anchor Properties
- π's digits are **deterministic but unpredictable** — the next digit cannot be predicted before computation, but can be independently verified after.
- The digit sequence is **irreversible** — consumed anchor bits cannot be returned.
- All entities share **one global anchor** — no local coordinate sequences, no fragmented anchors.

#### Triad Definitions (Software)

| Primitive | Definition | Why this definition |
|-----------|-----------|---------------------|
| **P · Primary Entity** | The acting subject of a computation task. Must be explicitly declared with four fields: `name`, `type` (LOGICAL / PHYSICAL / HUMAN), `boundary`, `unit`. | In software, the actor is an AI node or human — identity must be declared before action, otherwise audit is impossible. |
| **E · Execution Variable** | Variables used in the computation. Must be partitioned into **E_in** (controllable input: the subject may construct and modify) and **E_out** (uncontrollable output: the subject may only observe, never modify). | In software, variables are information carriers on the π-coordinate. The E_in/E_out partition prevents hallucinatory optimization — treating uncontrollable variables as if they were controllable. |
| **F · Final Result** | The output of the computation. Must be traceable to `(P, E, t)` where `t` is a moment on the π-anchor. Formal form: `F = f(P, E_in, E_out, t)`. | In software, results must carry provenance — which subject, with which variables, at which anchor coordinate. Without provenance, a result cannot be verified or reproduced. |

#### MOD3 — Three-State Interrogation (Software)
MOD3 in the software system is a **verification mechanism**, not an architecture structure. It subjects the same system to three interrogation intensities driven by the π-anchor (digit mod 3):

| State | Intensity | Role |
|-------|-----------|------|
| 0 | Loose | Normal operation — allows divergence, forbids final conclusions |
| 1 | Medium | Strict verification — allows constraint checking, forbids new divergence |
| 2 | Strict | Final adjudication — only PASS/FAIL, forbids vague terms |

MOD3 is resource scheduling, not randomness: loose state is power-efficient and low-latency; strict state is a reserved escape hatch with high safety margin.

#### Axioms (Software: A1–A8)
The software system is governed by eight axioms. Violation of any axiom triggers熔断 (circuit breaker):

| Axiom | Statement |
|-------|-----------|
| **A1** Unforgeability | Any position requiring an unforgeable coordinate must obtain it from the external π-source. Self-computation of π-digits triggers熔断. |
| **A2** Triad Completeness | Every computation must explicitly declare P, E, and F. Missing any primitive is invalid. |
| **A3** Variable Partition | E must be partitioned into E_in and E_out. Mixed variables trigger hallucinatory-optimization熔断. |
| **A4** Temporal Causality | Time proceeds in discrete, irreversible steps. A result cannot precede its cause. No downstream result may be referenced as upstream input. |
| **A5** π-Anchor Binding | Every code entity must bind to a unique π-anchor interval. Unbound entities are illegitimate. |
| **A6** Anchor Monotonicity | Consumed π-bits cannot be skipped or returned. The coordinate is strictly increasing. |
| **A7** Audit Traceability | Every F must be traceable to (P, E, t). Untraceable results are rejected. |
| **A8** Memory Alignment | (V2.3 addition) Cross-language memory layout must be aligned to the anchor coordinate, eliminating invisible dependencies. |

### System 2: Physical PEF (Thermodynamics-Anchored)

**Domain:** Hardware safety, physical control systems, high-reliability engineering
**Anchor:** Thermodynamic law — energy conservation, entropy increase, and the irreversibility of physical processes

#### Anchor Properties
- Thermodynamic laws are **unbreakable** — no device, no software, no agent can violate energy conservation or entropy increase.
- Potential differences (voltage, temperature, concentration, pressure) are **produced by thermodynamic gradients**, not by software declaration.
- Physical processes are **irreversible** — once energy is dissipated, it cannot be recovered without external work.

#### Triad Definitions (Physical)

| Primitive | Definition | Why this definition |
|-----------|-----------|---------------------|
| **P · Primary Entity** | The minimal independent physical or logical entity that executes actions and produces change. It is **the observed object**. | In physical systems, the entity is a real device or process — it is observed, not declared. Its identity is grounded in physical existence. |
| **E · Execution Variable** | The rules, parameters, energy flows, or constraints that act on the entity and drive its state evolution. It is **the driving force — the shift of potential difference produced by the thermodynamic anchor.** | In physical systems, variables are not information containers — they are energy flows and gradients. A variable exists only where there is a potential difference produced by the thermodynamic anchor. |
| **F · Final Result** | The stable state or irreversible effect the system reaches after variables act on the entity. It is **the terminal state of evolution.** | In physical systems, results are stable states or irreversible effects — not outputs to be consumed, but end states to be verified against physical constraints. |

#### PEF Three-Domain Cooperation (Physical)
In the physical system, the triad operates as three **processing domains** — this is an architecture structure, not a verification intensity:

| Domain | Role | Function |
|--------|------|----------|
| **P · Proposal Domain** | Generates strategy proposals, circuit topologies, or code suggestions based on current entity state. | Divergent generation |
| **E · Veto Domain** | Audits P-domain proposals with a destructive perspective, finds physical deadlocks, and exercises veto power. | Boundary monitoring — "is this proposal safe under current physical variables?" |
| **F · Adjudication Domain** | Performs final arbitration based on physical inequalities, outputs binary PASS/FAIL. | Evidence fusion and conflict resolution |
| **M · Final Review Layer** | Scheduler — drives the π-sequence (or thermodynamic clock) and maintains global state. | Orchestration |

**Boundary note:** In the physical system, this three-domain structure is sometimes called "MOD3" in internal documents. In the software system, "MOD3" refers to the three-state interrogation intensity. **These are different concepts sharing a name — the boundary is: physical MOD3 = architecture structure; software MOD3 = verification intensity.**

#### Physical Constraints (Thermodynamic Anchor)
The physical system is governed by thermodynamic law, not by software axioms:
- **Energy conservation:** ΣE_in = ΣE_out + ΣE_loss — any state evolution must balance energy.
- **Entropy increase:** irreversible processes increase total entropy — a "result" that decreases entropy without external work is physically impossible.
- **Potential difference grounding:** every E must trace to a thermodynamic gradient. A variable without a potential-difference source is illegitimate.

## What PEF Contributes

PEF does not invent new algorithms, new mathematical formalisms, or new control structures. The operator library contains 500+ existing algorithms; the state evolution equation is a standard state-space model; three-domain cooperation is a classic control architecture.

**PEF's contribution is anchored determinism:**

1. **Anchor-grounded variables** — every variable must trace to a potential difference produced by the anchor (π-coordinate in software, thermodynamic gradient in physics). No anchor, no variable. This eliminates hallucinated, ungrounded, or forged variables.

2. **Unforgeable provenance** — every result F traces to (P, E, t) on an anchor coordinate. The anchor cannot be predicted, rewound, or forged — so the provenance chain is objective and tamper-proof.

3. **Axiomatic circuit breaking** — violations are not "best practice violations" to be reviewed later. They are axiom violations that trigger immediate熔断. The system does not hope for correctness — it enforces it by construction.

4. **Cross-domain meta-pattern** — the same anchor→potential-difference→triad pattern works in both software (π-anchor) and physics (thermodynamics-anchor). This is not a single-domain trick — it is a meta-architecture that can be instantiated with different anchors.

**Honest positioning:** PEF is the assembly of existing components into an anchor-grounded, axiom-enforced, deterministically verifiable pipeline. The value is in the assembly — specifically, in the anchor that makes every component traceable and every transition legitimate.

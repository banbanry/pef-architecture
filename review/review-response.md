## 二、方向性误读（澄清，共 3 项）

| # | 评审观点 | 澄清 |
|---|---------|------|
| 1 | **"π 应整体降级为装饰，换成 UUID 功能不变"** | 部分同意、部分不同意。**同意**：π 不承担密码学角色，替换为自增序列号/UUID 不破坏架构主体。**不同意"装饰"定性**：π 有真实工程价值——**防向量坍缩**。LLM 的向量语义空间会把常数压成 `3.14` 这类短近似，毁掉持续坐标推演；π 的无限展开序列是模型"压不扁"的坐标素材（A1 形态约束保证）。这是评审按"密码学标准"评估时看不到的目标场景 |
| 2 | **"π-Mod3 的物理级公正是修辞重构"** | **同意**。已承认：π-Mod3 实质是 mod-3 计数器 + 固定偏移表，路径完全可预测。MOD3 的真实价值是**三档审问强度机制**本身（宽松/中等/严苛的资源调度），不依赖任何特殊常数——两种驱动方式可无缝替换，文档原本已声明 |
| 3 | **"生产案例（鸿鑫物流）无法公开验证"** | **同意**。公开仓库无法承载可核验证据。已调整为：**"已完成内部业务场景原型验证；完整生产级部署材料属于私有业务资料，不在本开源仓库公开"**。可公开验证的证据以 `examples/` 下的 Skill 实测为准 |

## 三、整改后价值再定位

外部评审的一个核心结论与作者一致：**剥掉 π 的形而上外壳后，PEF 的本体是一套标准但自洽的 LLM 工程审计流水线**：

```
无状态 LLM 工蜂（只做实体识别/结构提取）
  → M 层确定性内核（CRITIC 不等式 + SQLite + 哈希链）
    → C 层门控（矫正重试 + 状态印章）
      → 双轨分流（工程文本 / 非工程文本）
```

这套模式**不需要 π 也能工作**——这正是它的工程价值：**核心是分层审计架构，π 只是其中可替换的标记组件**。整改后的文档叙事已把这一层放到 C 位，π 降格为标记组件（防坍缩贡献单独说明，不混入安全声称）。

### 5.2 `get_pi_digit` 静默回退 → 显式报错

原实现：越界 `return 0`、绑定缺失 `pi_digit = 0`——100 位耗尽后被静默喂入错误数字。已改为：

```python
def get_pi_digit(n):
    if n <= 0 or n > len(pi_str):
        raise ValueError(f"pi digit out of range: {n}")   # 原: return 0
    return int(pi_str[n - 1])

# compute_phase / compute_r_forced 中：
if pi_digit is None:
    raise RuntimeError("pi binding missing: refuse silent fallback")  # 原: pi_digit = 0
```

### 5.3 C 层语义分离：审计发现 ≠ 结构失败

原逻辑把求解器 `FAIL`（**正确检出违规**）计入 `L4_no_contradiction=False → C_PASS=False`，合法审计结论被归类为系统校验失败。已拆为两个字段：

- `L4_structure_consistent`：结构完整（无 UNRESOLVED/异常）——决定 C_PASS
- `L4_falsification_found`：违规是否被检出（存在 FAIL 即 True）——进入终判给出 FAIL

14.2 示例同步修正：时序不等式 FAIL 时 `L4_structure_consistent=True, L4_falsification_found=True, C_PASS=True`，终判 `FAIL`（审计正确完成，而非校验失败）。UNRESOLVED/结构异常仍触发矫正流程。

### 5.4 A/B 对比表述收敛

"**能证明自己是对的**"→"**能证明每条结论出自哪里**"。π 坐标证明的是"可追溯到原文偏移"，不是"物理正确性"——数值真值来自 DataSheet 录入，锚定不验证真值。已同步 README、promotion-article、dsh-plugin-integration-plan、pimem、time-theory-appendix 共 5 处。

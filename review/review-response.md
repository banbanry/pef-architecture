## 一、属实指控（已整改，共 8 项）

| # | 指控 | 核实结果 | 整改动作 |
|---|------|---------|---------|
| 1 | **A1 公理"禁算 π"逻辑不可执行**：查表与自算数字相同、无法区分，熔断器永不触发 | ✅ 属实。旧 A1 约束"计算行为"，而该行为无法被观测 | **重写 A1 为"π-切片形态约束"**：只校验进入锚运算的**数据形态**（长度 + 数位完整性 + 切片来源），短近似直接拦截。见 `axioms.md` / `pi-anchor.md` |
| 2 | **"不可预测"在密码学上不成立**：π 是公开常数，BBP 算法可离线算任意位 | ✅ 属实。"不可预测"是过强断言 | **删除全部"不可预测/无法预测"声称**，改为"防向量坍缩 + 可复现分片"定位。见 `pi-anchor.md` 第一节 |
| 3 | **"不可预测"与"完全可复现"自相矛盾** | ✅ 属实。两处声称互相拆台 | **明确权衡声明**：本架构优先**可审计可回放**（可复现是核心收益），**牺牲不可预测性**；业务需不可预测时叠加外部会话随机种子 |
| 4 | **π 正规性被当作已证事实** | ✅ 属实。π 的正规性是**未证明的著名猜想** | 从工程公理中删除，归入【元理论思辨】；工程依据只使用已证明性质（无限不循环展开）。见 `axioms.md` 第三类 |
| 5 | **"召回率理论 100%"夸大** | ✅ 属实。实轨查询是关键词+标签正则匹配，标签丢失即漏检 | 改为"标签完整打标前提下高召回 + 标签丢失/文本改写时漏检的诚实边界"。见 design-spec 5.5.4 |
| 6 | **"纳秒级位比对、物理熔断"修辞过度** | ✅ 属实。√2 域本质是字符串黑名单过滤 | 降级为"字符串级别语义黑名单过滤，软件级拦截"，删除硬件化修辞。见 design-spec |
| 7 | **"不可被分叉"混淆日志防篡改与业务防分叉** | ✅ 属实。哈希链只能保证日志防篡改，不能阻止人为构造业务分支 | README 删除"unforkable"声称；`axioms.md` 明确安全能力真实来源（哈希链 + M 层权限隔离） |
| 8 | **硬件层无实测证据** | ✅ 属实。硬件方案只有白皮书 PDF，无仿真/波形/BOM/实测 | **涉专利，白皮书已从公开仓库移除**。公开文档明确：当前可落地形态为纯软件 LLM 审计流水线；硬件为推演设计 |

## 二、方向性误读（澄清，共 3 项）

| # | 评审观点 | 澄清 |
|---|---------|------|
| 1 | **"π 应整体降级为装饰，换成 UUID 功能不变"** | 部分同意、部分不同意。**同意**：π 不承担密码学角色，替换为自增序列号/UUID 不破坏架构主体。**不同意"装饰"定性**：π 有真实工程价值——**防向量坍缩**。LLM 的向量语义空间会把常数压成 `3.14` 这类短近似，毁掉持续坐标推演；π 的无限展开序列是模型"压不扁"的坐标素材（A1 形态约束保证）。这是评审按"密码学标准"评估时看不到的目标场景 |
| 2 | **"π-Mod3 的物理级公正是修辞重构"** | **同意**。已承认：π-Mod3 实质是 mod-3 计数器 + 固定偏移表，路径完全可预测。MOD3 的真实价值是**三档审问强度机制**本身（宽松/中等/严苛的资源调度），不依赖任何特殊常数——两种驱动方式可无缝替换，文档原本已声明 |
| 3 | **"生产案例（鸿鑫物流）无法公开验证"** | **同意**。公开仓库无法承载可核验证据。已调整为：**"已完成内部业务场景原型验证；完整生产级部署材料属于私有业务资料，不在本开源仓库公开"**。可公开验证的证据以 `examples/` 下的 Skill 实测为准 |

## 三、整改后价值再定位

外部评审的一个核心结论与作者一致：**剥掉 π 的形而上外壳后，PEF 的本体是一套标准但自洽的 LLM 工程审计流水线**：

```
无状态 LLM 工蜂（只做实体识别/结构提取）
  → M 层确定性内核（CRITIC 不等式 + SQLite + 哈希链）
    → C 层门控（矫正重试 + 状态印章）
      → 双轨分流（工程文本 / 非工程文本）
```

这套模式**不需要 π 也能工作**——这正是它的工程价值：**核心是分层审计架构，π 只是其中可替换的标记组件**。整改后的文档叙事已把这一层放到 C 位，π 降格为标记组件（防坍缩贡献单独说明，不混入安全声称）。

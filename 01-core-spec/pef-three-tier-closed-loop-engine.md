# PEF 三级闭环引擎设计规范

## PEF-CL (PEF Closed-Loop) — 内生循环 × 外部校准 × 多模型编译对齐

### 摘要

本规范定义 PEF 架构的**可执行认知引擎**：三级闭环流水线。它把固定内容（长文档 / 代码 / 知识库语料）转化为**可审计、可复算、可追溯的定案结论**，对抗大语言模型在长上下文处理中的三类不可治愈缺陷——注意力衰减、统计压缩、幻觉填充。

系统采用**权力剥夺式约束**：AI 被降级为无状态的结构提取工蜂；确定性能力（切块打分、信号分级、偏差裁决、锚定审计）全部外化至规则引擎与审计层。所有结论必须携带原文坐标锚点，所有偏差裁决必须通过统一 Schema 对齐，所有审计轨迹必须写入 π 锚哈希链账本。

**三级闭环：**
- **第一级 内生循环（token 深挖）** — 纯规则引擎，不烧外部 token。对固定内容切块、打分、分级、聚类，产出 S/A/B/C 四级定案与置信度。
- **第二级 外部校准（多模型偏差）** — 仅对低置信 / 块间分歧升级。多个独立主体（GLM / Claude / GPT）对同一任务各自裁决，探针前置过滤确定性错误。
- **第三级 多模型编译对齐（统一 Schema）** — 把异构模型输出编译成 P/E/F 三元 Schema，对齐比对计算偏差率 ρ，PASS 入账本、FAIL 熔断回流。

本规范适用于知识库体系深挖、长文本审计、跨模型代码协作治理等场景。不适用于开放域问答、创意写作等无锚定需求的任务。

## 第一章 问题定义：为什么要三级闭环

### 1.1 单一深挖不可证

仅靠规则引擎（内生循环）对固定内容做 token 级深挖，可以**发现**结构，但无法**证伪**结论。信号词典打分是启发式的——高机制词密度的文档会被判为 S 级精华，但"机制词多"≠"内容正确"。单级深挖的定案是**未经验证的假设**。

### 1.2 单一模型不可信

行业证据（Binghamton 零幻觉协议，7 LLM + RAG + 投票，10,000 次实验中 76.85% 获得 4+ 模型支持）表明：**多模型交叉验证是当前最有效的幻觉缓解策略**。OpenAI 幻觉理论（2025-09）进一步证明幻觉不可完全消除——单模型内部消除与多模型工程兜底是两个层面。依赖单一模型裁决，等于把信任押在一个统计采样器上。

### 1.3 异构输出不可比

多个模型对同一任务的输出天然异构：架构分割方言、错误处理方言、状态副作用方言、命名回调方言（CIC 文档四大指纹）。**不对齐就没法比**——"多模型偏差"要成立，前提是所有输出先编译成统一 Schema。这就是第三级"编译对齐"不可省略的原因。

### 1.4 三级闭环的回答

| 级 | 名字 | 回答的问题 | 成本 |
|---|---|---|---|
| ① | 内生循环 | "内容里到底有什么？哪些是核心？" | 几乎为零（规则引擎） |
| ② | 外部校准 | "内环说对了没有？换个主体还一样吗？" | 只花在低置信块上 |
| ③ | 编译对齐 | "多个模型的话对得上吗？偏差多大？" | 比对开销小 |

**核心命题**：便宜内环负责广度，严格外环负责深度，透明对齐负责裁决。三者缺一不可。

## 第二章 系统总览与全局架构

### 2.1 架构拓扑

```
固定内容输入（长文档 / 代码 / 知识库语料）
        │
        ▼
┌──────────────────────────────────────────────────────────────┐
│  ① 内生循环（token深挖引擎 · 规则层 · 零外部成本）              │
│  Pass1: 切块打分   600字/块 + 120字重叠 + P/E/F/M 信号词典      │
│  Pass2: 文档摘要   S/A块合并 → PEF三元摘要 + 核心句             │
│  Pass3: 聚类定案   跨文档机制词聚类 → S/A/B/C 分级              │
│  ┌─ 高置信（S级）→ 直接定案（π锚记录入账本） ───────────────┐  │
│  └─ 低置信 / 块间分歧 → 升级至外部校准 ──────────────────┐   │
└───────────────────────────────────────────────────────────┼──┘
        │                                                    │
        ▼                                                    │
┌───────────────────────────────────────────────────────────┐│
│  ② 外部校准（多模型偏差 · 校准层 · 只花低置信块）             ││
│  前置: 探针过滤（12个E层算子滤确定性错误）                    ││
│  GLM ──► 独立裁决                                           ││
│  Claude ──► 独立裁决                                        ││
│  GPT ──► 独立裁决                                           ││
└───────────────────────────────────────────────────────────┼──┘
        │                                                    │
        ▼                                                    │
┌───────────────────────────────────────────────────────────┐│
│  ③ 多模型编译对齐（统一Schema裁决层）                        ││
│  各模型输出 → 编译为 P/E/F 三元 Schema                       ││
│  → 对齐比对 → 偏差率 ρ                                      ││
│  ρ ≤ 阈值 → PASS → 定案入 π锚账本                           ││
│  ρ > 阈值 → FAIL → 熔断 → 标记待重挖 ────────────────────┼──┘
└───────────────────────────────────────────────────────────┘
        │
        ▼
  π锚审计账本（StateLedger + 哈希链 + 时序戳）
        │
        ▼
  PIMEM 记忆层（跨任务纵向复用，下一轮深挖直接读取）
```

### 2.2 数据流

- **P 层（主体）**：内生循环引擎（规则主体）+ 多模型（外部主体）——谁在做
- **E 层（变量）**：token 块、信号分、置信度、偏差率 ρ、统一 Schema——用什么做
- **F 层（结果）**：PASS/FAIL 裁决、定案表、审计记录——得到什么
- **M 层（元认知）**：熔断回流、待重挖标记、PIMEM 记忆存取——如何演进

### 2.3 权力分离

| 权力 | 归属 | 禁止 |
|---|---|---|
| 切块 / 打分 / 分级 | 规则引擎（内生循环） | AI 不可自定义分级标准 |
| 独立裁决 | 多模型（外部校准） | 单一模型不可终判 |
| 对齐 / 偏差计算 | 编译对齐层 | AI 不可自评偏差 |
| 终审 / 熔断 | F 层裁决模块 | 调度器不可自审自判 |
| π 锚分配 | 外部数学脚手架 | 任何层不可创造或修改 π |

## 第三章 第一级：内生循环（token 深挖引擎）

### 3.1 设计目标

对固定内容做**全量、不跳读、不靠文件名猜**的 token 级遍历，产出结构化定案。纯规则、零外部 token 成本、全透明可复算。

### 3.2 参数

| 参数 | 值 | 说明 |
|---|---|---|
| CHUNK_SIZE | 600 字 | 单块大小 |
| OVERLAP | 120 字 | 相邻块重叠，防切块边界截断语义 |
| S 级阈值 | M≥3 或 (F≥6 且 total≥10) | 核心结论块 |
| A 级阈值 | total≥6 | 机制描述块 |
| B 级阈值 | total≥2 | 过程 / 例子块 |
| C 级 | 其余 | 噪声块 |

### 3.3 P/E/F/M 信号词典（核心指纹）

| 词典 | 词数 | 代表词 |
|---|---|---|
| P_SIGNALS（主体） | 36 | 本架构/PEF/P域/E域/F域/M层/引擎/模型/算子/探针/智能体/Agent/硬件/芯片/FPGA/主体/节点/头雁/校验者/仲裁者/CLE/CIC/GLM/Claude/GPT |
| E_SIGNALS（变量） | 34 | 变量/输入/输出/参数/状态/阈值/置信度/偏差/漂移/上下文/token/向量/锚/π/pi/哈希/日志/链路/时序/E_in/E_out/熵/势差/温漂 |
| F_SIGNALS（结果） | 32 | 结果/结论/裁决/判定/通过/失败/PASS/FAIL/熔断/拒绝/交付/判决/允许/禁止/闭环/验证/定案/停机/回退/ALLOW/DENY/证据/验收 |
| MECH_SIGNALS（机制） | 28 | 公理/铁则/熔断/审计/锚定/隔离/时序/因果/不可伪/平权/异构/否决/裁决/MOD3/拜占庭/影子图/雁阵/漂移校验/三层纪律/第一性原理/三元/流水线/状态机 |

### 3.4 Pass1：切块与打分

```python
def pass1(text: str) -> list[Block]:
    """token级切块 + P/E/F/M信号打分"""
    blocks = []
    for i in range(0, len(text), CHUNK_SIZE - OVERLAP):
        chunk = text[i:i + CHUNK_SIZE]
        scores = score_signals(chunk)   # P/E/F/M 四维
        total = sum(scores.values())
        level = classify_block(scores, total)  # S/A/B/C
        blocks.append(Block(
            doc_id=doc_id, seq=i // (CHUNK_SIZE - OVERLAP),
            text=chunk, scores=scores, total=total,
            level=level, hash=sha256(chunk).hexdigest()[:16],
        ))
    return blocks
```

### 3.5 Pass2：文档级三元摘要

S/A 级块按文档聚合 → 每文档输出：
- **P/E/F/M 信号分**（四维聚合）
- **core**：S 级块核心句 Top3（机制词密度最高的句子）
- **dom_pef**：主导域（P/E/F 中信号分最高者）
- **level**：文档级定案（S / A / B / C）

### 3.6 Pass3：跨文档聚类

- 全局机制词计数（跨全部块）
- 按 (level, dom_pef) 聚类文档
- 输出全局主题 + 未知文档定案

| 块数 | 8,480 块（S 2,580 / A 3,808 / B 1,509 / C 583） |

## 第四章 第二级：外部校准（多模型偏差）

### 4.1 触发条件

仅以下情况升级到第二级（成本控制铁则）：
- 文档级 level 为 A/B（机制不足，需外部判断）
- S 级文档内存在**块间矛盾**（同文档 S 级块 P 域与 F 域信号冲突）
- 跨文档聚类发现**同主题文档定案冲突**

### 4.2 探针前置（确定性错误过滤）

升级前先跑 E 层算子（12 个 CLE 探针）过滤确定性错误：
E033 空包占位符 / E056 逻辑链断裂 / E034 死代码 / E022 数学性质 / E040 字符串有效 / E035 未实现声明 / E039 缓冲区溢出 / E041 未初始化内存 / E043 资源泄漏 / E150 整数溢出 / E049 路径覆盖 / E042 数据竞争。

**目的**：探针能查出的错误不花模型 token；多模型只比"探针查不出的语义分歧"。

### 4.3 多模型独立裁决

```python
def external_calibrate(block: Block, probes: list[Probe]) -> list[Verdict]:
    """多模型独立裁决：探针前置 + 三主体并行"""
    # 1. 探针过滤
    for probe in probes:
        findings = probe.run(block.text)
        if findings.critical:
            return [Verdict(model="probe", verdict="FAIL",
                            reason=findings.summary)]
    # 2. 多模型并行（只对剩余低置信块）
    prompts = build_unified_prompt(block)   # 统一任务模板
    return [ask_model(m, prompts) for m in (GLM, CLAUDE, GPT)]
```

| 证据 | 来源 | 与本级关系 |
|---|---|---|
| 7 LLM + RAG + 投票零幻觉 | Binghamton STAR Protocols 2026-05 | 多模型交叉验证有效性的直接证据 |
| 幻觉不可完全消除 → 校准与约束 | OpenAI 2025-09 | 单模型内消 vs 多模型外兜的理论依据 |
| 多模型验证是最有效缓解策略 | Suprmind 幻觉基准 2026-07 | 行业共识 |

## 第五章 第三级：多模型编译对齐（统一 Schema）

### 5.1 为什么必须编译对齐

多模型输出异构（CIC 四大指纹：架构分割 / 错误处理 / 状态副作用 / 命名回调）。不对齐就无法计算偏差——**"方言偏差 = 空间化的公理漂移，同病同方同治"**（PEF-CIC 核心命题）。统一 Schema 就是让异构模型的话"能对上"的翻译层。

### 5.2 统一 Schema：P/E/F 三元

每个模型的输出编译为：

```json
{
  "P": {"name": "模型标识", "role": "裁决者", "boundary": "仅对输入块负责"},
  "E": {"inputs": ["<输入块hash>"], "variables": ["<提取变量>"],
        "confidence": 0.0-1.0, "anchor": "π[i]=d|domain|model"},
  "F": {"verdict": "PASS|FAIL|UNKNOWN", "evidence": ["<核心句>"],
        "reason": "<一句话理由>"}
}
```

P/E/F 三元是 PEF 第一性原理的最小完备描述——谁在做、用什么变量做、得到什么结果。任何模型输出都能无损映射到这个 Schema。

### 5.3 偏差率 ρ 计算

```python
def compute_rho(verdicts: list[Verdict]) -> float:
    """偏差率：多模型裁决不一致程度（spec-as-region 口径）"""
    n = len(verdicts)
    if n < 2:
        return 0.0
    # 主偏差：裁决结果不一致比例
    verdicts_set = {v["F"]["verdict"] for v in verdicts}
    mismatch = 1.0 if len(verdicts_set) > 1 else 0.0
    # 证据偏差：核心句语义重叠度（Jaccard，token级）
    evidence_sets = [set(tokenize(v["F"]["evidence"])) for v in verdicts]
    avg_jaccard = mean(
        jaccard(evidence_sets[i], evidence_sets[j])
        for i in range(n) for j in range(i+1, n)
    )
    # 置信偏差：置信度分歧
    conf_spread = max(v["E"]["confidence"] for v in verdicts) - \
                  min(v["E"]["confidence"] for v in verdicts)
    return 0.5 * mismatch + 0.3 * (1 - avg_jaccard) + 0.2 * conf_spread
```

### 5.4 裁决与熔断

| ρ 区间 | 裁决 | 动作 |
|---|---|---|
| ρ ≤ 0.15 | **PASS** | 定案入 π锚账本（P 域 / E 域 / F 域 / 时序四层洋葱哈希） |
| 0.15 < ρ ≤ 0.4 | **REVIEW** | 标记人工复核候选，入账本待审 |
| ρ > 0.4 | **FAIL** | 熔断，块标记"待重挖"，回流内生循环 |

### 5.5 诚实边界

ρ 是**裁决一致性的度量，不是真值概率**。多模型一致 ≠ 正确（所有模型可能共享同一训练分布偏差）。ρ 的价值在于**可追溯的分歧检测**，而非绝对正确性保证。

## 第六章 π锚审计与记忆层

### 6.1 π锚审计账本（StateLedger）

```
每条记录: { anchor_id, domain, seq, t_anchor, payload, prev_hash, chain_hash }
- π锚坐标: π[i]=digit|domain|source_type（不可伪造，外部查表）
- 时序铁则: t_state ≤ t_anchor ≤ t_write（不可倒果为因）
- 哈希链: onion_hash(内容→时序→域→锚) 层层包裹
- 只追加: 禁删除、禁修改（篡改即断链）
```

### 6.2 与 PIMEM 记忆层衔接

横向闭环（单次任务）产出 → 纵向 PIMEM（跨任务）：
- π-基因链三元组：主体生命周期演化谱系
- 审计链-记忆树双向索引：任务时间线 × 知识结构树正交
- 反回注漂移三纪律：记忆读取不修改内环参数，防预演污染

```bash
# 一键运行三级闭环
pef-cli mine --input <dir|file> [--output verdict.json] [--models glm,claude,gpt]

# 只跑内生循环（零成本）
pef-cli mine --input <dir> --tier 1

# 只做编译对齐（输入已有模型输出）
pef-cli align --verdicts <verdicts.json> [--threshold 0.15]

# 审计查询
pef-cli audit --ledger <ledger.db> --block <block_hash>
```
